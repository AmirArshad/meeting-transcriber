# AvaNevis v3.0.0 Design and Implementation Plan

**Branch:** `release/3.0`  
**Date:** 2026-11-20  
**Goal:** Ship AvaNevis **v3.0.0** by closing every mandatory post-v2.12 reliability, runtime, security, signing, and platform-qualification gate, upgrading to a modern in-app auto-updater (Claude Desktop / ChatGPT Desktop style), and delivering local History full-text search and grounded Q&A with clickable timestamp citations.

**Approach:** Deliver in five sequenced phases so pure-engineering wins land first, runtime/signing prerequisites unlock real in-place auto-updates, and History search lands cleanly before local-LLM Q&A builds on top of it. Keep every change strictly local-only, plain HTML/CSS/JS on the renderer, Electron `src/main/` service isolation, and Python 3.11 per-invocation subprocesses.

**Constraints (canonical contracts — read before editing each surface):**
- **Privacy & Local AI:** No cloud processing, telemetry, analytics, or hidden background downloads. User Hugging Face tokens remain exclusively in async `safeStorage` and validated stdin boundaries. All GPU work serializes on `aiComputeActionQueue`. See [local-ai.md](../../development/contracts/local-ai.md).
- **Recording & Persistence:** Separate durable `{stem}.capture/` spools mixed after stop; atomic `FileLock` + temp-file + `os.replace()` metadata writes; saved `.md` remains the human-readable transcript source of truth; derived AI/search artifacts live under Electron `userData`, never the repo. See [recording.md](../../development/contracts/recording.md) and [meeting-persistence.md](../../development/contracts/meeting-persistence.md).
- **Packaging & Platforms:** Windows 10/11 x64, macOS 15+ Apple Silicon (`arm64`), and Linux x86_64 (supported Omarchy/CachyOS Hyprland/Wayland/PipeWire vs experimental tiers). Preserve Linux opaque device IDs, managed CUDA fail-closed rules + Repair/Uninstall escape paths, Speakrs-only Linux diarization, and `AVANEVIS_PACKAGED=1` path hardening. See [packaging.md](../../development/contracts/packaging.md).
- **IPC & Facades:** Change owning `src/main/` service, `src/preload.js`, every renderer caller, and characterization tests together; keep `src/main.js` a composition root and preserve pinned export key sets in `src/main-process-helpers.js` and `src/ai-addon-setup.js`. See [ipc.md](../../development/contracts/ipc.md).

## Phase 1: Reliability, Caption-Scale Timing & Subtitle Export

Pure engineering deliverables with zero external signing or hardware blockers. Closes two mandatory post-v2.12 gates and establishes millisecond-accurate caption sidecars that Phase 4's timestamped search also leverages.

### Task 1.1: Eliminate History Metadata Lock Contention During Slow Recorder Recovery

**Problem:** In `backend/meeting_manager.py`, `scan_and_sync_recordings()` holds `self._metadata_guard()` (`FileLock`, 10 s timeout) across the entire scan, including `meeting_scan.recover_or_cleanup_recorder_temps(self.recordings_dir)` (which may `shutil.copy2` large `.pcm.tmp` files on slow storage), directory enumeration, placeholder creation, and transcript duration reads. Concurrent History reads/writes/deletes/renames time out waiting on `meetings.json.lock`.

**Files:**
- `backend/meeting_manager.py` — refactor `scan_and_sync_recordings` into bounded lock phases while preserving instance method seams.
- `backend/meetings/scan_import.py` — add a dedicated scan-recovery lock helper or clean separation between filesystem preparation and metadata commit verification.
- `src/main/recordings-maintenance-gate.js` — verify gate ownership (`scan` vs `recovery` vs `start`) remains aligned with shortened metadata-lock windows.
- `tests/python/test_meeting_manager.py` and `tests/python/test_recorder_temp_and_scan_recovery.py` — add concurrent metadata operation regressions during slow recovery.

**Implementation:**
1. **Separate recovery I/O from `_metadata_guard()`:**
   - Guard recorder-temp promotion/cleanup (`recover_or_cleanup_recorder_temps`) with a separate `scan_recovery.lock` (so two simultaneous scans do not race temp promotion) rather than holding `meetings.json.lock`.
   - Do **not** hold `_metadata_guard()` during slow `.pcm.tmp` copies, directory iteration, symlink/path resolution, or reading existing `.md` files to parse duration.
2. **Preserve import-transaction & commit atomicity (per `meeting-persistence.md`):**
   - Phase A (short `_metadata_guard()`): reconcile `.meeting-import-<id>` markers via `_reconcile_import_transactions_unlocked()` and snapshot existing audio filenames / IDs. Release lock.
   - Phase B (unlocked, under `scan_recovery.lock`): run `recover_or_cleanup_recorder_temps()`, discover candidate scannable audio files, filter against snapshot, extract durations from existing canonical `.md` files, and prepare candidate descriptors (do **not** write placeholder `.md` files until commit verification so an active import or delete cannot be raced).
   - Phase C (short `_metadata_guard()`): re-run `_reconcile_import_transactions_unlocked()`, re-read current metadata from disk, re-verify each candidate still exists, is not a symlink, has no active sibling `.capture/` dir, and is still absent by filename and ID; only then write missing pending placeholders and atomically commit all newly discovered meetings in **one** metadata write (`temp` + `os.replace()`).
3. **Preserve crash/corrupt-metadata invariants:** If `meetings.json` is unreadable/corrupt during Phase A or C, retain existing corrupt-backup behavior and never delete unverified import markers or candidate files.

**Validation:**
- Add a deterministic multi-process/multi-thread Python regression where `recover_or_cleanup_recorder_temps` is slowed (monkeypatched seam sleeping/blocking on an event) while concurrent `list_meetings`, `update_meeting` (rename), `add_meeting`, and `delete_meeting` execute and succeed immediately without hitting `FileLock` timeout, followed by clean scan completion with zero duplicate or lost records.
- Run: `npm run test:python -- -k "meeting_manager or scan_recovery"` and `node --test tests/js/recordings-maintenance-gate.test.js`.

### Task 1.2: Persist Caption-Scale Timing Sidecars & Ship Accurate SRT / WebVTT Exports

**Problem:** `backend/transcription/formatting.py` merges transcription segments to ~20 s chunks (`target_duration=20.0`) and truncates timestamps to whole seconds (`[MM:SS - MM:SS]`). Shipping SRT/WebVTT from `.md` alone loses cue boundaries and sub-second precision.

**Files:**
- `backend/transcription/captions.py` *(new)* — pure cue segmentation/normalization (`build_caption_cues`, schema v1 serializer/validator, caption-length/duration splitting with word-timestamp support when available).
- `backend/transcription/formatting.py` — keep `.md` formatting unchanged for backwards compatibility; expose shared transcript-hash helper if not already shared.
- `backend/transcription/faster_whisper_transcriber.py`, `backend/transcription/mlx_whisper_transcriber.py`, `backend/transcription/parakeet_transcriber.py`, `backend/transcription/parakeet_segments.py` — preserve pre-merge fine-grained segments (millisecond `start`/`end`, plus word timings when cheap/available without regressions) in result JSON alongside merged `.md` segments.
- `backend/diarization/guided_transcription.py` and `backend/diarization/speaker_segments.py` — retain per-utterance fine cues with `speaker` labels before 20 s Markdown merging.
- `backend/meeting_manager.py`, `backend/meetings/paths.py`, `backend/meetings/delete_tx.py`, `backend/meetings/scan_import.py` — persist/commit `{stem}.captions.json` atomically alongside transcript commit, store `captionsPath` / `captionsSourceTranscriptHash` in meeting metadata, clean up on delete, and invalidate/replace on re-transcription (failed attempts preserve prior sidecar).
- `src/main/transcription-service.js` — pass cue segments through commit path and clear stale caption metadata on re-transcription failure/replacement identically to speaker sidecars.
- `src/renderer/subtitle-export-helpers.js` *(new)* — pure SRT (`HH:MM:SS,mmm`) and WebVTT (`WEBVTT\n\n` + `HH:MM:SS.mmm`) serializers, speaker-prefix formatting (`Speaker 1: ...` / `<v Speaker 1>` option), overlap/monotonicity clamping, Unicode preservation, and cue validation.
- `src/main/file-export-ipc.js` — generalize `buildSafeSaveDialogDefaultPath(suggestedName, extension)` (preserving `WINDOWS_RESERVED_FILE_BASENAME` sanitization!) and extend `save-transcript-as` to accept explicit `format` (`'md' | 'txt' | 'srt' | 'vtt'`) plus verified meeting ID / caption sidecar validation in main (so main loads and validates `sourceTranscriptHash` against the current `.md` on disk before exporting subtitles).
- `src/preload.js`, `src/renderer/app.js`, `src/renderer/index.html`, `src/renderer/styles.css`, `src/renderer/history-detail-helpers.js` — explicit export format picker (popover/dialog) before opening the native save dialog on both History detail and post-recording Save As callers (leaving Summary Save As untouched).
- `tests/python/test_captions.py` *(new)*, `tests/python/test_transcriber_helpers.py`, `tests/python/test_meeting_manager.py`, `tests/js/subtitle-export-helpers.test.js` *(new)*, `tests/js/file-export-ipc.test.js` *(new or existing export tests)*.

**Implementation:**
1. **Caption sidecar schema (`{stem}.captions.json`, v1):**
   ```json
   {
     "schemaVersion": 1,
     "sourceTranscriptHash": "<sha256 of committed .md>",
     "engine": "faster-whisper | mlx-whisper | parakeet",
     "timingPrecision": "segment | word",
     "cues": [
       { "startMs": 1570, "endMs": 4610, "text": "...", "speaker": "Speaker 1" }
     ]
   }
   ```
   - Cue shaping rules: split overly long raw segments (> 7 s or > 84 chars) cleanly on punctuation/word boundaries when word timestamps exist; enforce monotonic non-negative `startMs < endMs` (minimum 100 ms duration for non-empty text); never drop spoken words; never alter the saved `.md` source of truth.
2. **Hash provenance & legacy meetings:**
   - Main verifies `captions.sourceTranscriptHash === sha256(current .md)` before allowing SRT/WebVTT export.
   - If a meeting predates v3.0 (no `.captions.json`) or the user edited the `.md` externally so hashes diverge:
     - **Markdown (`.md`)** and **Plain Text (`.txt`)** exports remain immediately available.
     - **SRT (`.srt`)** and **WebVTT (`.vtt`)** options display an honest status note (*"Accurate subtitles require caption-scale timing. Re-transcribe from the saved audio to generate cue timings."*) with a one-click **Re-transcribe** action when source audio is present. Never fabricate fake millisecond timestamps from 20 s Markdown blocks.
3. **Export UX & Windows safety:**
   - Export picker lets the user select `.md`, `.txt`, `.srt`, or `.vtt` *before* the OS save dialog opens so the dialog's default extension, filename sanitization (`buildSafeSaveDialogDefaultPath`), and file filter agree.
   - Keep `save-transcript-as` backwards-compatible for any caller that passes raw `content` without `format` (defaults to `.md`).

**Validation:**
- Unit tests covering SRT comma vs WebVTT dot milliseconds, `>= 1 hour` rollovers, zero-length/overlapping cue clamping, speaker labels, RTL/CJK/emoji Unicode, Windows reserved basenames (`CON`, `NUL`, `COM1`), hash mismatch rejection, legacy meeting fallback, and Save Dialog cancel.
- Integration test: transcribe real repository speech fixture with Whisper and Parakeet → verify `.captions.json` written with matching `sourceTranscriptHash` → export `.srt` and `.vtt` → verify first/last cue timing matches audio duration and delete removes `.captions.json`.
- Focused commands: `npm run test:python -- -k "captions or transcriber or meeting_manager"` and `node --test tests/js/subtitle-export-helpers.test.js tests/js/main-process-helpers.test.js`.

## Phase 4: Local History Search & Grounded Q&A with Timestamp Citations

Delivers AvaNevis v3.0's flagship user feature: instant full-text search across every recorded and imported meeting (zero AI add-on required), layered with local grounded Q&A using the installed `llama.cpp` + Qwen summary runtime and verified clickable citations that jump straight to audio playback at the exact timestamp.

### Task 4.1: Local SQLite FTS5 Index & Instant Full-Text History Search with Timestamp Jump

**Architecture:** Use Python 3.11's standard-library `sqlite3` with FTS5 (`porter unicode61` tokenizer) — **zero new Python or Node dependencies**. The index lives at `userData/search/history-index.sqlite` as a strictly disposable derived cache; `meetings.json` + `.md` + `.captions.json` + summary sidecars remain the authoritative sources of truth.

**Files:**
- `backend/search/__init__.py` *(new)*
- `backend/search/history_index.py` *(new)* — SQLite FTS5 schema, incremental sync, passage chunker, BM25 query engine, snippet highlighter, and corruption auto-rebuild.
- `backend/search/cli.py` *(new)* — per-invocation JSON CLI (`sync`, `search`, `rebuild`, `status`) invoked via `src/main/python-runtime.js`.
- `src/main/history-search-service.js` *(new)* — main-process service serializing index syncs/queries, enforcing trusted paths, triggering incremental syncs after meeting mutations (`add`, `update`, transcript commit, summary commit, `delete`, `scan`), and exposing IPC.
- `src/main/meeting-manager-client.js`, `src/main/transcription-service.js`, `src/main/summary-service.js`, `src/main.js`, `src/preload.js` — hook mutation notifications into `historySearchService.markDirty()` / incremental sync; register `search-history`, `rebuild-history-index`, `get-history-index-status`.
- `src/renderer/history-search-helpers.js` *(new)* — pure search query debouncing, result grouping by meeting, safe snippet highlight rendering, and timestamp-target resolution.
- `src/renderer/app.js`, `src/renderer/index.html`, `src/renderer/styles.css` — upgrade History sidebar search from title-only filtering to full-text search across titles, transcripts, speakers, and summaries, showing matched snippet + `[MM:SS]` timestamp pill; clicking a hit opens the meeting, scrolls to & highlights the matching transcript segment, and seeks `<audio>` to `startSec`.
- `tests/python/test_history_index.py` *(new)* and `tests/js/history-search-helpers.test.js` *(new)*.

**Implementation:**
1. **SQLite schema (`userData/search/history-index.sqlite`, WAL mode, `busy_timeout=5000`):**
   - `index_meta(key, value)` — stores `schema_version = 1`.
   - `indexed_meetings(meeting_id PRIMARY KEY, title, date_iso, language, transcript_hash, summary_hash, captions_hash, updated_at)`.
   - `passages(passage_id INTEGER PRIMARY KEY, meeting_id, kind /* 'transcript' | 'summary' */, start_ms, end_ms, speaker, text, source_transcript_hash)` + `passages_fts` (`USING fts5(title, speaker, text, content='passages', tokenize='unicode61 remove_diacritics 2')`).
   - Passage granularity:
     - When hash-matched `{stem}.captions.json` exists: group fine cues into ~15–25 s / ~300–500 char searchable passages preserving exact `start_ms` of the first cue and `end_ms` of the last cue (plus `speaker` when uniform).
     - Legacy meetings without `.captions.json`: parse existing `**[MM:SS - MM:SS]**` / `**[HH:MM:SS - HH:MM:SS]**` blocks directly from `.md` so all historical v1/v2 meetings are immediately searchable with timestamp jump!
     - Summary sidecar (when hash-matched): indexed as `kind='summary'` (`start_ms=NULL`) so searching key decisions/action items also surfaces the meeting.
2. **Consistency & deletion safety:**
   - Every `sync` compares live `meetings.json` against `indexed_meetings`: inserts new meetings, re-indexes changed hashes, and **hard-deletes** passages for removed meetings so deleted recordings can never leak into search or Q&A results.
   - Any `sqlite3.DatabaseError` / corrupt index triggers an atomic temp-file rebuild without failing History browsing.
3. **Timestamp deep-linking in History viewer:**
   - Add a pure helper to match a target `startSec` to the closest rendered transcript timestamp block in History detail, scroll it into view, apply a temporary highlight ring, and set `audio.currentTime = startSec` (handling audio metadata load cleanly if the meeting was just opened!).

**Validation:**
- Python tests: index build over mixed v2 legacy `.md`, v3 `.captions.json`, speaker-labelled, multilingual (CJK/Spanish/Hindi), and summary-bearing meetings; incremental update on rename/re-transcribe; zero leaked hits after `delete_meeting`; corrupt `.sqlite` auto-recovery; query escaping for FTS5 special chars (`"`, `*`, `OR`, `-`, `:`).
- JS tests: snippet rendering (XSS-safe escaping!), result grouping, timestamp-to-block resolution, and keyboard navigation through search results.
- Commands: `npm run test:python -- -k "history_index"` and `node --test tests/js/history-search-helpers.test.js`.

### Task 4.2: Grounded Local Q&A Backend (`retrieval`, `qa_runner`, `citation_verifier`) & Compute Queue Wiring

**Architecture:** Strictly local-only RAG over the SQLite FTS5 index from Task 4.1, powered by the user's already-installed local summary runtime (`llama.cpp` + Qwen 3.5 9B/4B) through `aiComputeActionQueue`.

**Files:**
- `backend/history_qa/__init__.py` *(new)*
- `backend/history_qa/retrieval.py` *(new)* — deterministic local retrieval over `history-index.sqlite`: extracts keywords/phrases from the user's question, runs scoped BM25 FTS5 search (`all`, `single_meeting`, `selected_meetings`, optional date range), merges adjacent passages for local context, deduplicates overlapping spans, and packs top-K numbered evidence blocks `[E1]…[En]` under a strict UTF-8-byte prompt budget (reusing `bytes / 4` sizing under the 32,768-token context, reserving headroom for system instructions + answer generation).
- `backend/history_qa/qa_runner.py` *(new)* — CLI entrypoint reusing `backend/summaries/llama_runtime.py` (`resolve_llama_runtime`, `build_llama_cli_args`, offline HF env) to run Qwen with strict grounded-citation prompt and structured JSON output; emits structured progress lines on stdout and respects SIGTERM/cancel cleanly.

- `src/main/history-qa-service.js` *(new)* — main-process service:
  - Enforces **identical runtime readiness & platform GPU gates** as `summary-service.js` (`checkAiAddonSetupStatus({ verifyChecksums: true, verifyChecksumsIfChanged: true })`, Linux CUDA gate, no CPU/cloud fallback).
  - Runs fast index sync + retrieval preflight **before** claiming `aiComputeActionQueue` (so empty/zero-hit queries return an instant *"No matching passages found in your History"* without waiting on or occupying the GPU!).
  - Enqueues the `qa_runner.py` subprocess on `aiComputeActionQueue` wrapped in `runWallClockComputeAction` (new `AI_COMPUTE_TIMEOUT_MS.historyQa`, e.g., 10 min), supports `cancel-history-qa`, and terminates cleanly during `drainAiWorkBeforeQuit`.
- `src/main-process/compute-timeout-helpers.js` (and `src/main-process-helpers.js` facade if constants are exported — verify export key-set characterization tests!).
- `src/main.js`, `src/preload.js` — wire `ask-history`, `cancel-history-qa`, `get-history-qa-eligibility`, and `history-qa-progress` event.
- `tests/python/test_history_qa.py` *(new)* and `tests/js/history-qa-service.test.js` *(new)*.

**Implementation:**
1. **Strict Grounded Response Contract:**
   ```json
   {
     "status": "answered | insufficient_evidence",
     "answer": "In the Q4 Planning sync [E1], the team agreed to delay launch to November [E2].",
     "citations": [
       {
         "evidenceId": "E1",
         "meetingId": "20261115_100000",
         "meetingTitle": "Q4 Planning",
         "startSec": 862,
         "endSec": 884,
         "speaker": "Speaker 1",
         "excerpt": "..."
       }
     ],
     "searchedMeetingCount": 24,
     "evidenceCount": 6
   }
   ```
   - **Never let the LLM invent meeting IDs or timestamps.** The LLM only sees opaque IDs `E1`..`En` and cites `[E1]`; `citation_verifier.py` resolves every `[Ek]` back to the immutable indexed passage metadata.
   - If the model cites an unknown ID (e.g. `[E99]`), strip the invalid citation; if the answer has zero valid citations on a factual claim or the model sets `insufficientEvidence: true`, clearly mark the response as insufficient evidence rather than presenting unsupported claims.
2. **Queue & Privacy invariants:**
   - User-triggered only (never runs speculative background LLM inference).
   - Never mutates any meeting metadata, `.md` transcript, or summary sidecar.
   - Multi-turn follow-up within the current Ask History session may include bounded prior Q&A turns in-memory (capped by UTF-8 byte budget) and re-runs retrieval per question so every follow-up stays freshly grounded against live History (respecting meetings deleted mid-session!).

**Validation:**
- Python unit tests: retrieval scoring & UTF-8 budget cap (including multilingual/CJK inputs), JSON repair on malformed model output, hallucinated `[E99]` citation rejection, `insufficient_evidence` detection, and deleted-meeting exclusion.
- JS service tests: readiness/checksum fail-closed, zero-hit fast path (no GPU queue acquisition), `aiComputeActionQueue` serialization with transcription/summary, cancellation, wall-clock timeout settlement, and quit drain.

## Cross-Cutting Risks & Design Decisions

| Risk / Decision | Mitigation |
|---|---|
| **Code signing & Apple Developer enrollment lead time** | Phase 1 (lock fix, caption timing, SRT/VTT) and Phase 4 (History Search & Q&A) have zero signing dependency and can proceed in parallel with obtaining/configuring Windows & Apple signing credentials. Phase 3 code/tests can also be written ahead of credentials, with live updater acceptance gated on Task 2.3. |
| **Auto-updater vs AvaNevis no-hidden-downloads invariant** | Keep `autoDownload = false` by default (metadata check only, one-click in-app download + restart), and provide an explicit opt-in Settings toggle for background auto-download like Claude/ChatGPT Desktop. Never auto-restart during recording, import commit, or summary metadata finalization. |
| **Windows Authenticode signing vs Speakrs CLI integrity hash** | If signing touches `Resources/bin/speakrs-cli.exe`, recompute/verify the packaged Speakrs manifest hash against the signed binary (or sign only app/installer boundaries if `speakrs-cli.exe` is hash-pinned at prepare-time) and confirm `verify-speakrs-packaging.js --packaged` passes before release. |
| **Linux `pacman`/`.deb` cannot self-update in place** | Explicitly support full in-app swap on `AppImage` (`process.env.APPIMAGE`) and provide a first-class manual-package update flow (verified download + copyable `pacman`/`apt` command) on system installs rather than failing silently. |
| **LLM hallucinated citations in History Q&A** | Never let the LLM generate meeting IDs or timestamps. Retrieve numbered evidence blocks `[E1]…[En]` deterministically from SQLite FTS5, require inline `[Ek]` references, and resolve/strip citations fail-closed in `citation_verifier.py`. |
| **Legacy v1/v2 meetings without `.captions.json`** | For SRT/WebVTT export: fail closed to MD/TXT + one-click re-transcribe (never invent fake millisecond cues). For History Search & Q&A: index parsed `[MM:SS - MM:SS]` Markdown blocks so all historical meetings remain immediately searchable and citable with timestamp jump. |
| **FFmpeg upstream parity** | Do not split FFmpeg versions across platforms; hold until Windows x64, macOS arm64, Linux x64, and `ffmpeg.org` source tarball match on the same pinned version. |
