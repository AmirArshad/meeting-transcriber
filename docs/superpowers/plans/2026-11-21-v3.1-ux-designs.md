## 1. Visual Language & Design System Alignment

All v3.1 surfaces build inside AvaNevis's existing calm, local-first dark palette defined in `src/renderer/styles.css` (`:root` lines 5–80) using plain HTML, CSS, and modular `src/renderer/*-helpers.js` helpers (no React/Vue, zero raw `innerHTML` for untrusted data):

- **Surfaces:** `--surface-0` (`#101214`), `--surface-1` (`#171a1d`), `--surface-2` (`#202428`), `--surface-3` (`#252a2e`), `--surface-4` (`#2b3136`), `--surface-glass` (`rgba(23, 26, 29, 0.94)`).
- **Borders / Hairlines:** `--hairline` (`#343a40`), `--hairline-strong` (`#434a50`), `--hairline-soft` (`#292e32`).
- **Text:** `--text-primary` (`#e7e9e6`), `--text-secondary` (`#b8bfbc`), `--text-tertiary` (`#838b88`), `--text-quaternary` (`#626966`).
- **Accents & Semantics:** `--accent` (`#b8a8c9`), `--accent-strong` (`#d0c2de`), `--sky` (`#a8b0c8`), `--emerald` (`#65ad8a`), `--amber` (`#d2a85c`), `--crimson` (`#df6b6b`).
- **Typography & Motion:** `--font-display`, `--font-sans`, `--font-mono`, `--focus-ring`, and `@media (prefers-reduced-motion: reduce)` parity across all transitions and spinners.
- **Plain Operator Copy:** User-facing copy uses `recording`, `audio`, and `Summaries & Chat` (preserving internal `meeting*` DOM IDs/IPC names per [ipc.md](../../development/contracts/ipc.md)).

## 2. Upgraded Chat Workspace (`#chat-tab`)

### Goals
1. Eliminate opaque `"Not enough matching information..."` dead ends by surfacing honest retrieval vs. reasoning states with actionable recovery buttons.
2. Make cross-recording and tag-scoped queries effortless (`All recordings · Interview`, `From 2026-09-05`) and show progressive streaming output while generating locally.

### Layout & Component Upgrades

```text
+-----------------------------------------------------------------------------+
| [Sidebar] Active Thread Title · [2 recordings] · [Tag: Interview]  [Loaded] |
|-----------------------------------------------------------------------------|
|  User bubble:                                                               |
|    "what key points came up in the recording from 05/09/2026"               |
|                                                                             |
|  Assistant turn (streamed live via SSE -> finalized with verified pills):   |
|    ## Key Points                                                            |
|    - Confirmed the Q4 beta freeze date [Sync · 04:12]                       |
|    - Alice will handle the Linux installer test [Sync · 09:40]              |
|                                                                             |
|    ▸ Sources (4) · Searched 2 recordings · Used summary + 3 transcript cues |
|-----------------------------------------------------------------------------|
|  [Error/Notice example — replaces generic amber box:]                       |
|  +-----------------------------------------------------------------------+  |
|  | ! No transcripts matched "05/09/2026" in the current filter.          |  |
|  |   Searched 2 selected recordings · Date filter parsed: 2026-09-05     |  |
|  |   [Search all recordings]  [Clear date filter]                        |  |
|  +-----------------------------------------------------------------------+  |
|-----------------------------------------------------------------------------|
| [Scope: All · Interview ▾]  Ask a question…                       [Send/Stop]|
+-----------------------------------------------------------------------------+
```

### Key UX Details
1. **Live Streaming & Cancel:**
   - During generation (`executionMode === 'server'`), `#chat-progress-banner` transitions smoothly into a live draft bubble inside `#chat-messages` showing sanitized answer prose as tokens arrive, paired with an active **Stop** button (`#chat-send-btn` toggled to cancel state). On completion, `citation_verifier.py` replaces the draft with `renderGroundedMarkdown()` and verified `[Meeting Title · MM:SS]` pills.
2. **Honest Failure & Empty States (Three Distinct Callout Variants):**
   - `no_matching_excerpts`: Neutral/slate info notice (`"No matching passages found in <scope>."`) + detected date/tag hint + inline quick actions (**Search all recordings**, **Reset filters**).
   - `insufficient_evidence`: Calm amber callout (`"Found 4 passages, but they don't answer that specific question."`) + expandable **Sources inspected** drawer so the user can see what was checked + **Try broader wording** / **Search all recordings** button.
   - `verification_failed`: Muted crimson/amber recoverable notice (`"The local model returned an unverified format."`) + one-click **Retry** button.
3. **Enhanced Scope Popover (`#chat-scope-popover`):**
   - Adds a compact **`Filter by tag`** pill row (multi-select toggle pills covering tags used in History, with a compact `"All 11 types"` expand toggle when needed) right above the existing `#chat-scope-dates-row` (`From` / `To`) and `#chat-scope-selected-panel`.
   - `#chat-scope-btn-label` and `#chat-header-scope` show concise combined scope summaries via `formatChatScopeLabel()` (e.g., `All recordings · Interview`, `2 recordings · 2026-09-05`, `All recordings`).
4. **Human Speaker & Tag Metadata in Citations:**
   - `#chat-messages` Sources drawer displays resolved human speaker names (`Alice` instead of `Speaker 1`) and a subtle muted tag chip next to the recording date.

## 3. Recording Tags System

### Canonical Tag Palette (11 Non-Overlapping Types) & Summary Templates

Tags use subtle low-saturation tinted pills against `--surface-2` with `--hairline` borders (never bright neon badges that clash with AvaNevis's calm editorial palette). Each tag selects its own dedicated summary template:

| Slug | Display Label | Subtle Tint / Accent Token | Dedicated Summary Format Sections |
|---|---|---|---|
| `meeting` | `Meeting` | `--accent` (`#b8a8c9`, 12% soft fill) | Summary, Topics, Decisions, Action Items, Risks, Open Questions |
| `appointment` | `Appointment` | `--sky` (`#a8b0c8`, 12% soft fill) | Overview, Key Findings, Advice & Guidance, Next Steps, Prep / Instructions, Questions |
| `call` | `Phone / Support Call` | `--sky` / steel-slate soft fill | Overview, Call Details (Refs / Dates / Amounts), Outcomes & Commitments, Next Steps, Unresolved Issues |
| `interview` | `Interview` | `--sky` / cool-teal subtle fill | Overview, Background & Themes, Key Q&A, Notable Quotes, Signals & Highlights, Follow-ups |
| `lecture` | `Lecture / Study` | `--accent-strong` / slate-violet soft fill | Overview, Core Concepts, Examples & Cases, Key Takeaways, Study Questions |
| `podcast` | `Podcast` | `--accent` / muted plum-slate soft fill | Overview, Chapters & Segments, Key Insights, Notable Quotes, References Mentioned |
| `video` | `Video` | `--accent-strong` / slate-indigo soft fill | Overview, Sections, Key Takeaways, Demos / Steps, References Mentioned |
| `voice-note` | `Voice Note` | `--emerald` (`#65ad8a`, 11% soft fill) | Summary, Key Thoughts, Ideas, Reminders & To-Dos, Open Questions |
| `brainstorm` | `Brainstorm` | `--emerald` / muted sage-slate soft fill | Overview, Problem / Goal, Ideas Explored, Standout Concepts, Tradeoffs, Next Experiments |
| `music` | `Music` | `--amber` (`#d2a85c`, 11% soft fill) | Session Overview, Musical Ideas, Lyrics & Themes, Mix & Arrangement, Next Takes |
| `other` | `Other` | `--surface-3` / `--text-secondary` | Summary, Key Points, Outcomes & Takeaways, Next Steps, Open Questions |
| *(unset / legacy)* | *(Untagged)* | Dotted `--hairline` `"Add tag"` ghost pill | Falls back cleanly to `Other` general summary format |

### Placement Across Five Surfaces

1. **History Detail Header (`.meeting-detail-header`, `index.html:941-998`):**
   - Right inside `.meeting-meta` beside `#meeting-date` and `#meeting-duration`:
     ```text
     Amir Andy Sync  [✎]
     Nov 18, 2026 · 14:22 · [Meeting ▾]
     ```
   - Clicking the tag pill opens a clean 2-column anchored popover grid (all 11 tags with color dots + `Clear tag`), commits immediately via `window.electronAPI.updateMeeting(id, { tag })`, updates the list item + FTS5 index, and supports `Escape` / arrow-key navigation.
2. **History Sidebar (`#history-tab` `.history-sidebar`, `index.html:894-928`):**
   - Below `.sidebar-search` (`#meeting-search`) and above `#selection-toolbar`: a compact single-row scrollable chip strip (`All`, plus tags currently present in History — keeping the sidebar uncluttered while every assigned tag is 1 click away).
   - Each recording row in `#meeting-list` shows its compact tag dot/pill cleanly alongside duration/date without truncating titles.
3. **Home Recording Controls & Activity Row (Optional, Non-Blocking):**
   - A compact optional `"Tag: Meeting ▾"` pill tucked beside the recording language/model header or on Home Activity rows (`renderActivityList`), allowing tag assignment before, during, or right after recording without slowing down one-click **Start Recording**.
4. **Audio Import Modal (`#import-audio-fields`, `index.html:20-55`):**
   - Add an optional `Recording tag` `<select>` (`None (untagged)` + 11 canonical tags) inside `#import-audio-fields` so imported files enter History already categorized.
5. **Summary Tab Tag-Mismatch Notice (`#history-summary-panel`, `index.html:1106-1125`):**
   - If a recording already has a summary generated under one tag (e.g. `Meeting`) and the user later changes the recording's tag to `Appointment`, show a non-blocking subtle banner below `#history-summary-panel`'s toolbar:
     `Tag changed to Appointment. [Regenerate with Appointment format]`
   - Existing summary remains fully readable and searchable in FTS5.

## 4. Speaker Label Assignment UX (`Speaker N` → Human Names)

### Design Principles
- **Fast voice identification:** Users rarely remember whether `"Speaker 1"` or `"Speaker 2"` spoke first. Pairing each speaker row with a 1-line quote preview and a `▶ 00:14` play button bound to `#audio-player` makes naming speakers take seconds.
- **Zero interruptions after recording:** Never modal-block `stopRecording()`. Surface a lightweight non-blocking prompt after diarization finishes.
- **Optional pre-summarization nudge:** Gently ask once before summarizing *only* when unnamed `Speaker N` labels exist, inside the existing `#summary-language-modal` (no modal stacking).

### Surface 1: History Transcript Speaker Bar (`#history-transcript-panel`)

Placed directly below `.history-detail-toolbar` and above `#meeting-transcript` (hidden when a recording has no diarized speakers; auto-collapses into compact summary chips once all speakers are named):

```text
+-----------------------------------------------------------------------------+
| Transcript   Language: English   [Generate summary] [Copy] [Save]           |
|-----------------------------------------------------------------------------|
| Speakers (2) · Click a name to update transcript, search, summaries & export|
| +-----------------------------------+ +-----------------------------------+ |
| | [▶ 00:08] "Let's check the..."   | | [▶ 00:21] "Sure, I pushed the..." | |
| | Speaker 1 -> [ Amir            ]  | | Speaker 2 -> [ Andy            ]  | |
| +-----------------------------------+ +-----------------------------------+ |
+-----------------------------------------------------------------------------+
| [00:08 - 00:19]  [Amir]                                                     |
| Let's check the Linux build status before tagging.                          |
+-----------------------------------------------------------------------------+
```

- **Interactions:**
  - Clicking `[▶ 00:08]` seeks `#audio-player` via `seekMeetingAudio(startSec)` and starts playback of that speaker's first audible segment (toggles to `❚❚` while playing that snippet).
  - Editing `[ Amir ]` commits on `Enter` or blur (saving via `updateMeeting(id, { speakerNames })`); `Escape` reverts the input; clearing the input reverts back to `Speaker 1`.
  - Clicking any speaker badge inside `#meeting-transcript` (e.g., `[Speaker 1]`) expands the Speaker Bar if collapsed and focuses that speaker's input field.

### Surface 2: Post-Recording / Post-Transcription Non-Blocking Prompt

- In Home's `renderActivityList()` (`onTranscriptionQueueState` → `status === 'ready'`): when the completed job detected `>= 1` diarized speakers (`speakerCount >= 1`), display a secondary pill **`Name speakers`** next to **`Open in History`**.
- The completion toast (`#activity-completion-toast`) includes a quick **`Name speakers`** link when diarized speakers exist. Clicking it navigates to History, selects the recording, expands the Speaker Bar, and focuses the first unnamed `Speaker 1` input.

### Surface 3: Optional Pre-Summarization Prompt Inside `#summary-language-modal`

Reuses and widens `#summary-language-modal` cleanly (`max-width: 480px`) without stacking two dialogs:

```text
+-------------------------------------------------------+
| Prepare summary                                   [×] |
|-------------------------------------------------------|
| Transcript language                                   |
| [ English                                         ▾ ] |
|                                                       |
| Speaker names (optional)                              |
| Give speakers real names so the summary attributes    |
| decisions and tasks accurately. Leave blank to keep   |
| Speaker 1, Speaker 2.                                 |
|                                                       |
|  Speaker 1  [ Amir            ]  [▶ 00:08]            |
|  Speaker 2  [                 ]  [▶ 00:21]            |
|                                                       |
| Recording type (optional — shown only if untagged)    |
| [▾ Choose tag (optional): Meeting / Call / Lecture… ]  |
| Format: Other (Key Points, Outcomes, Next Steps…)       |
|                                                       |
|                        [ Cancel ]  [ Generate summary ]|
+-------------------------------------------------------+
```

- **Behavior:**
  - The **"Speaker names (optional)"** fieldset renders **only** when the recording has diarized speakers with at least one unnamed `Speaker N` (or can be collapsed behind an `"Edit speaker names"` toggle once all are named).
  - The **"Recording type (optional)"** strip renders compactly only if the recording is currently untagged (using a compact `<select>` or 2-column tag picker + a 1-line **Format preview** showing the sections that template produces), helping users get the right summary template with one click.
  - **`Generate summary`** is always immediately enabled — the user can ignore speaker names/tag and hit `Enter` / click `Generate summary` immediately with zero friction. If any names or tag were entered, `app.js` saves them via `updateMeeting()` first, then triggers `generateSummary()`.
  - Focus-trap logic in `app.js` dynamically queries visible inputs inside `#summary-language-modal` so keyboard `Tab` navigation stays trapped correctly.

## 5. Settings → Summaries & Chat Model Selector (`#summary-addon-card`)

### Design Pattern Alignment
Mirrors the existing Speakrs / Pyannote radio-card group (`role="radiogroup"`, `.diarization-engine-radio` in `src/renderer/index.html`) so Settings stays cohesive, scannable, and honest about hardware requirements.

```text
+-----------------------------------------------------------------------------+
| Summaries & Chat                                              [ Ready ✓ ]   |
| Generate summaries on demand and ask questions in Chat. All models run      |
| locally via llama.cpp (Apache 2.0, no account required).                    |
|                                                                             |
| Local model                                                                 |
| +-------------------------------------------------------------------------+ |
| | (•) Qwen3.5 9B · Default                              [Active · 5.7 GB] | |
| |     Balanced speed, multilingual summaries & citation accuracy (8 GB+)  | |
| +-------------------------------------------------------------------------+ |
| | ( ) Gemma 4 E4B                                      [Apache 2.0 · ~5.8 GB]|
| |     Strong reasoning & Q&A on 8 GB+ GPUs / 16 GB+ Macs (128K ctx)       | |
| +-------------------------------------------------------------------------+ |
| | ( ) Gemma 4 12B                                     [Apache 2.0 · ~7.5 GB]|
| |     Higher summary & synthesis quality for 12–16 GB+ GPUs / 24 GB+ Macs | |
| +-------------------------------------------------------------------------+ |
| | ( ) Qwen3.5 4B · Compact                            [Apache 2.0 · 2.7 GB]|
| |     Fastest option for 6 GB VRAM / 8 GB unified memory                  | |
| +-------------------------------------------------------------------------+ |
| | ( ) Inkling 2 Mini · High Memory                    [~17 GB · 24 GB+ GPU]|
| |     26B MoE looped reasoner (3.4B active). Needs 24 GB VRAM / 32 GB Mac | |
| +-------------------------------------------------------------------------+ |
|                                                                             |
| Summary style: [ Balanced ▾ ]                                               |
|                                                                             |
| Model file: Qwen3.5-9B-Q4_K_M.gguf (5.68 GB) · Shared llama.cpp: Installed  |
| Ready. Generate summaries from any transcript or ask questions in Chat.     |
|                                                                             |
| [ Switch to Gemma 4 12B ]  [ Check setup ]  [ Disable and remove… ]         |
+-----------------------------------------------------------------------------+
```

### Interactive & Accessibility States
1. **Exclusive Active Model (Shared Runtime):**
   - Only one GGUF model is installed at a time to protect disk space, while the `llama.cpp` runtime binary lives in shared `userData/ai-addons/runtimes/llama-cpp/<runtimeId>/` so switching models **reuses** the installed `llama.cpp` runtime instead of re-downloading 500 MB+ of CUDA/Metal libraries.
   - Selecting a different radio card does **not** mutate disk state immediately: it updates the primary CTA label (`Switch to Gemma 4 E4B` / `Set up Gemma 4 12B`) and footprint preview (`~5.8 GB model · runtime already installed`), matching `getDiarizationSetupButtonLabel()`.
2. **Switch Confirmation & Safety Unload:**
   - Clicking `Switch to <Model>` opens a confirmation dialog (`window.confirm` / modal): `"Switching from Qwen3.5 9B to Gemma 4 E4B will download ~5.8 GB, verify the new model, and remove Qwen3.5 9B (5.68 GB) after validation succeeds. Your shared llama.cpp runtime and past summaries remain intact."`
   - Main automatically unloads any resident Chat `llama-server` (`beforeSummaryAddonMutation()`), validates/smoke-tests the new GGUF before deleting the old GGUF (atomic fallback on cancel/failure), and disables radio controls while `downloading` or `validating`.
3. **Hardware & Platform Honesty:**
   - If a model's minimum runtime build (`>= b12600` for Inkling 2 Mini) is not yet available for the user's platform, its card shows a clear disabled/unsupported pill (`"Requires upcoming Linux CUDA runtime update"`) rather than failing mysteriously at runtime.
   - Selecting a high-memory model (`Gemma 4 12B` or `Inkling 2 Mini`) displays an inline muted `--amber` hardware advisory (`"Recommended: 24 GB+ VRAM or 32 GB+ Apple Silicon memory"`) without hard-blocking knowledgeable desktop users.

## 6. Accessibility & Responsive Guarantees

- All interactive tag chips, speaker preview buttons, and model radio cards support full keyboard navigation (`Tab`, `ArrowLeft`/`ArrowRight` or `ArrowUp`/`ArrowDown` inside `role="radiogroup"`, `Enter`/`Space` activation, `Escape` to dismiss popovers) and visible `--focus-ring`.
- Narrow viewports (`< 900px`): Chat scope chips wrap cleanly; History Speaker Bar stacks speaker cards into a single column; Settings model cards wrap badge chips onto a second line cleanly without horizontal overflow.
- All animations (`chat-progress-spinner`, streaming caret, speaker bar collapse) respect `@media (prefers-reduced-motion: reduce)`.
