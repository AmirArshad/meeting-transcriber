# AvaNevis v2.12.0 scope and implementation plan · November 18, 2026

Someone who already has a meeting recording should be able to pick it from disk, transcribe it locally and reopen the result in History. This is the next use for the queue shipped in v2.6, the transcription choices shipped in v2.10 and the speaker setup refreshed in v2.11. Import is the release headline. Subtitle export gives the same user a way to take the timed result into a video editor, and also benefits meetings already in History.

## Build order and release scope

1. Capture the dependency baseline and the Windows banner behavior on v2.11.0. Begin the routine pin updates and native runtime qualification first. Feature development can proceed while matching hosts become available.
2. Use the [audio import design prompt](2026-11-18-audio-import-design-prompt.md) to map the v2.11 interface, choose the History entry point and specify a small visual cleanup. Deliver import end to end with one WAV through History and Activity. Then cover MP3, Opus, interruption, disk pressure and queue contention on the same path.
3. Exercise subtitle export on existing transcripts as well as imported ones. It is the first feature to move to a later release if timing quality or schedule requires it.
4. Integrate qualified updates, repeat dependency discovery at release cut, run the integrated suite and qualify the packaged user journey. Track implementation in [todo.md](../../../todo.md).

## 2. Import one local recording into History

Add **Import audio** in History through src/renderer/index.html and src/renderer/app.js. Show the selected language and engine before enqueue. Route the native picker through src/preload.js and a new src/main/audio-import-service.js registered in src/main.js. Main owns the selected file and resolves the bundled FFmpeg. Accept one local MP3, WAV or Opus, require a decodable audio stream and restrict decoding to the selected local input. Stream to a unique app-owned subdirectory beneath the recordings directory. The top-level scan in backend/meetings/scan_import.py ignores nested files, and the existing main and Python path checks require both staged inputs to stay within recordings. Normalize to playable Opus with the bundled FFmpeg and derive duration from the decoded audio. Show conversion progress or a cancellable busy state for long recordings.

Pass only the verified, app-owned audio copy to src/main/meeting-manager-client.js and backend/meeting_manager.py. The existing add path may remove its input after commit. Use the filename stem as the initial title and the ordinary meeting ID for storage. Call the main-owned finalizeRecordingTranscription path with the staged audio, duration, title and frozen selection. Its placeholder, add-meeting transaction and attempt ID persist audio and the pending transcription selection before admission to the existing FIFO in src/main/transcription-service.js. A crash after commit must leave a resumable meeting. Before commit, cancellation, low disk space or decode failure must leave the source intact and no History entry. Keep a single import operation active. On quit, drain or cancel conversion before cleanup. Once commit starts, settle it before reporting the outcome and use normal Activity cancellation for the pending job. Clean abandoned import staging on restart. Verify that interruption while copying final files cannot expose a partial meeting via rescan. If the existing add transaction leaves such orphans, add recoverable commit bookkeeping under the metadata lock and cover this boundary with a restart test. Summary generation remains a separate user action.

Exercise all three formats using real encoded audio, corrupt and empty input, same-name files, cancellation, restart, deletion and an import queued behind active work. Check source bytes after failure and after deleting the imported meeting. Verify playback, retry, speaker eligibility and user-triggered summary through the same History controls as a recording. Follow the [persistence](../../development/contracts/meeting-persistence.md), [IPC](../../development/contracts/ipc.md) and [local AI](../../development/contracts/local-ai.md) contracts and update them where the interface changes.

## 3. Export timed transcripts if the schedule allows

The shared Markdown formatter truncates timestamps to whole seconds and can merge segments into roughly 20-second chunks. First inspect actual Whisper, Parakeet, speaker-labelled and older Markdown outputs against backend/transcription/formatting.py. Use timing tied to the current saved transcript. Add a pure cue serializer and extend src/main/file-export-ipc.js and both Save As callers in src/renderer/app.js, carrying format selection through src/preload.js. Offer an explicit export format before opening the native dialog so the serializer, suggested extension and filter agree. Keep the shared summary Save As caller on its current formats. Offer SubRip (.srt) and WebVTT (.vtt) for usable timing. Preserve speaker labels and Unicode. Explain unavailable timing for legacy or untimed text and keep Markdown and plain text available. Never invent timings or overwrite the saved transcript through an export default.

Check cue numbering, SRT comma and VTT period separators, hour boundaries, invalid or zero-duration cues, and cancel from the native save dialog. Open a generated subtitle alongside its source audio and verify first and last cue timing. Defer both subtitle formats together if existing transcript precision cannot produce reliable cues without changing the transcription pipeline.

## Release decision

Run focused JS and Python regressions while iterating, then npm run test:all on integrated inputs. On packaged Windows x64, macOS 15+ arm64 and supported Linux x86_64, import a real local clip, play it, transcribe, restart and reopen it. Exercise subtitle playback if included. Use npm run build on Windows, npm run build:mac and npm run verify:mac:packaged on Apple Silicon, and npm run build:linux and npm run verify:linux:packaged on supported Linux. Include an upgrade from a disposable v2.11 profile with existing History, a pending job and installed models. Record host and artifact evidence separately from CI. At release preparation update package.json and the root lockfile version, write docs/releases/v2.12.0.md with actual shipped scope and holds, and reconcile the roadmap and todo status. The import workflow and preservation of the original file determine feature readiness. Reassess runtime candidates individually at release cut.

## What earns v3.0

The roadmap allows a major new feature or a breaking change. Recent releases expanded platform coverage, model choice and speaker identification. v2.12 makes those capabilities available to existing recordings while preserving the current workflow and data. Recommend a minor release.

A stronger v3 milestone is answering a question across several meetings locally. A user should be able to search existing and imported transcripts, ask what was decided, follow each answer citation into timestamped playback, and see when the transcripts contain insufficient evidence. Validate that workflow with old History data and after meeting deletion. Start with transcript search and source navigation, then evaluate grounded answers on the installed local model. Live captions, private sync, silent installation, Apple notarization and AUR publishing each have separate architecture or distribution dependencies and can be scheduled independently.
