# AvaNevis v2.11 Speakrs 0.7 and Electron 46 Implementation Plan

> **For agentic workers:** Work inline on the existing branch. Delegate only when the user explicitly asks. This is an execution plan, not evidence that a platform or release has passed.

**Goal:** Upgrade Speakrs to 0.7 for Windows CUDA, Linux CUDA, and macOS CoreML, and move AvaNevis to the latest available Electron 46, while preserving existing data, privacy, supported platforms, and operational behavior.

**Architecture:** Continue to ship the app's own offline, installer-bundled Rust CLI and use explicit catalog-driven setup for model assets. Adapt its contract and native runtime integration to Speakrs 0.7 separately for Windows CUDA, Linux CUDA, and macOS CoreML. Migrate all synchronous Electron safeStorage use and callers to async before qualifying Electron 46. Promote each platform only after native packaged inference and migration checks; the requested release is not complete until all three pass.

**Tech Stack:** Electron 46, plain JavaScript/HTML/CSS, Python 3.11, Rust, Speakrs 0.7, NVIDIA CUDA, macOS CoreML.

## Scope, decisions and evidence as of 2026-11-10

- Product target is **Speakrs 0.7.0 on Windows x64 CUDA and Linux x86_64 CUDA**, and **Speakrs 0.7.0 on macOS arm64 CoreML**. Windows is in scope, not a future follow-up. No CPU fallback is permitted for shipped speaker identification on any of these paths. CI-only CPU smoke, if retained, is a separate test tool and must never widen the product policy.
- Product target is the **latest available Electron 46**. On 2026-11-10 npm reports `46.0.0-alpha.8` as the latest 46 and `45.2.3` as the latest stable Electron; no stable 46 is published. Implement and test against a specific exact 46 version, recording whether it is alpha/beta/stable, its release notes and actual binaries. Recheck the registry at implementation and release time; upgrade to the latest suitable 46 and repeat affected checks when it changes. Clearly label pre-release candidates and do not represent them as stable. Stable 46 and its final release notes are the preferred release baseline when available; record any remaining alpha/beta limitation honestly.
- The initial branch updates Electron 45.2.1 to 45.2.3 in `package.json` and `package-lock.json`. This is preliminary work, not the new target. Replace that candidate with the chosen 46 version as part of this plan.
- The previous Linux spike used an isolated 0.7 CUDA CLI with default features disabled and a Rust 1.89 toolchain. It compiled and passed seven Rust tests. An offline short-fixture run on RTX 4070 matched current 0.5 output, but both produced one speaker, so it does **not** qualify multi-speaker accuracy. Nothing from that temporary spike has been integrated into the product.
- Upstream 0.7 documents native CUDA on Linux and native CoreML on macOS; upstream Windows CUDA support is not established. Treat Windows native compilation, DLL loading, inference and packaging as a first-class feasibility task. If Windows requires a minimal audited source patch or fork, document its provenance, license, reproducibility, maintenance and security consequences and test it natively. Do not silently retain 0.5, switch to CPU/cloud, mark the feature supported, or drop Windows from this release if this task fails. Continue other independent work and record an explicit Windows blocker.
- AvaNevis's 0.5 CLI invokes `make_exclusive()`; 0.7 exposes `exclusive_segments` and `segments` and changes post-processing. Rust 1.89 is its declared minimum. Verify the actual resolved dependency graph's Rust requirements instead of assuming the minimum is sufficient.
- 0.7's upstream model revision is `67f963b6a1d94fcd4678948237b3cc8bd69bf1d8`. The Linux spike verified real CUDA bytes for `segmentation-3.0.safetensors`, size 5,897,576, SHA-256 `88e7883cf56f679170e162419efddf970f929915281ebce80e351c42b5a7115d`; and `wespeaker-multimask-tail.safetensors`, size 26,527,656, SHA-256 `b97b090ceebcf10924732ad4552a2d867d76d38dcc1409a13687a6ba71ff1ef3`. Re-verify these and enumerate all other platform-specific assets from actual upstream bytes. They are candidate evidence, not sufficient catalog qualification.
- v2.11 is a provisional release name. Do not bump app version, stage, commit, push, tag, publish, change repository settings, or dispatch workflows without separate user authorization.
