# AvaNevis v3.2.0 Design and Implementation Plan

**Branch:** `release/3.2` (proposed)  
**Date:** 2026-11-22  
**Goal:** Ship AvaNevis **v3.2.0** by fixing the real-world v3.1.0 field issues across model compatibility assessment, Gemma 4 12B VRAM fit calibration, unload-before-download model setup UX, Chat context routing & follow-up continuity, granular timestamp citations, optional general chat (recording-free) mode with guardrails, ≥5-second speaker voice samples with explicit `"Sample"` labeling, and an always-available summary format selector — while unifying `llama.cpp` on `>= b12631` to unblock **Inkling 2 Mini** across all three platforms, expanding the curated model library with **Bonsai 2** and mainstream 12B–35B peers, and sweeping **Electron 46**, FFmpeg, Python, and Rust dependencies.

**Approach:** Deliver in five sequenced phases so hardware fit & install blockers land first, Chat retrieval/context/citations/general-chat overhaul cleanly without breaking existing thread storage or XSS/grounding invariants, speaker-sample and summary-format UX improvements stay tightly scoped, the unified `llama.cpp >= b12631` runtime unlocks Inkling 2 Mini + Bonsai 2 (`Q2_0`) + peer models without adding a custom engine fork, and platform dependency/qualification gates close before release cut. Keep every feature 100% offline/local, plain HTML/CSS/JS on the renderer (`src/renderer/*-helpers.js`), isolated in `src/main/` services, and run via per-invocation Python 3.11 subprocesses.

**Constraints (canonical contracts — read before editing each surface):**
- **Privacy & Local AI:** No cloud inference, telemetry, analytics, or hidden downloads. Tokens stay in async `safeStorage` and validated stdin boundaries. One model process runs at a time (`src/main/summary-process-slot.js`), serialized with GPU work on `aiComputeActionQueue` / `gpuResourceActionQueue`. Keep Linux managed CUDA 12 fail-closed rules and Repair/Uninstall paths. See [local-ai.md](../../development/contracts/local-ai.md).
- **Recording & Persistence:** Atomic `FileLock` + temp-file + `os.replace()` metadata writes; saved `.md` remains the immutable transcript source of truth; derived FTS5 search and Chat threads live under Electron `userData`. See [meeting-persistence.md](../../development/contracts/meeting-persistence.md).
- **Packaging & Platforms:** Preserve Windows 10/11 x64, macOS 15+ Apple Silicon (`arm64`), and Linux x86_64 (Omarchy/CachyOS Hyprland/Wayland/PipeWire supported vs experimental tiers), Linux opaque device IDs, Speakrs-only Linux diarization, and `AVANEVIS_PACKAGED=1` path hardening. See [packaging.md](../../development/contracts/packaging.md).
- **IPC & Facades:** Update owning `src/main/` service, `src/preload.js`, every renderer caller, and characterization tests together; keep `src/main.js` a composition root and preserve `src/main-process-helpers.js` / `src/ai-addon-setup.js` export key sets and `AI_ADDON_PROGRESS_CHANNEL` / `AI_ADDON_CANCEL_CODE`. See [ipc.md](../../development/contracts/ipc.md).

## Critical Path & Token-Optimized Execution Strategy

To avoid the oversized multi-thousand-line diffs and repeated full-suite reruns that burned tokens in v3.1, v3.2 splits the five spec phases into **10 tight, mostly file-disjoint micro-slices (~120–400 diff lines each)** across **3 integration checkpoints** on `release/3.2`, load-balanced between **Antigravity** (`Neon`, `Argon`, `Terra`) and **Codex** (`Sol`) in a shared `t3code` workspace:

```text
Wave A — Quick Wins & Hardware Fit (can run A1, A2, A3 in parallel worktrees; A4 follows A3)
  ├── Slice A1: Speaker ≥5s samples + "Sample" label (#8, #9)        [Phase 3 · Task 3.1]
  ├── Slice A2: Summary format dropdown + ai.summary.template (#10)  [Phase 3 · Task 3.2]
  ├── Slice A3: Device fit states, 12 GB calibration & Linux probe   [Phase 1 · Task 1.1]
  └── Slice A4: Unload-before-download prompt + stale state fixes    [Phase 1 · Task 1.2]
  ──► CHECKPOINT 1: Merge A1–A4 to release/3.2 → 1x npm run test:all + CachyOS smoke

Wave B — Chat Context, Precise Citations & General Chat (strict backend → UI split)
  ├── Slice B1: Python 3-tier context router, follow-ups & granular timestamps (#3, #4, #11)
  ├── Slice B2: General chat backend (scope='none') & verifier guardrails (#5, #11)
  └── Slice B3: Chat renderer UI (General chat, Clear context, Summary pills) (#5, #11)
  ──► CHECKPOINT 2: Merge B1–B3 to release/3.2 → 1x npm run test:all + live Chat smoke

Wave C — Unified Runtime, Expanded Models & Dependencies
  ├── Slice C1: Unified llama.cpp >= b12631 runtime + Inkling 2 Mini unblock [Task 4.1]
  ├── Slice C2: Bonsai 2 (Q2_0) & curated peer models (#7)                   [Task 4.2]
  └── Slice C3: Electron 46, FFmpeg check, Python/Rust sweep & contracts     [Phase 5]
  ──► CHECKPOINT 3: Merge C1–C3 to release/3.2 → final test:all, audits, native builds & v3.2.0 cut
```

### Token-Budget Guardrails (for $20 Antigravity + $20 Codex via `t3code`)

1. **One slice = one fresh session:** Never carry prior slice chat history into the next slice. Start each slice cold pointing only at its specific Task section in this plan and the exact 3–5 files listed.
2. **Diff-only cross-tool reviews:** Feed reviewers `git diff release/3.2...HEAD` (200–400 lines) plus the slice's 3 invariants — never ask a reviewer to re-read whole 12k-line files like `app.js` unless a specific symbol needs context.
3. **Skip heavyweight reviews on trivial slices:** Only **A4** (process-slot concurrency), **B1** (retrieval/context router), **B2** (general-chat epistemic guardrails), and **C1/C3** (runtime ELF & Electron `safeStorage`) warrant **Argon**/**Sol** deep review.
4. **Tiered test cadence:** Run only the focused test command per slice; run `npm run test:all` once per Checkpoint (3 times total instead of 15+), logging verbose output to ignored files.
5. **Script metadata fetches:** Collect Hugging Face commit SHAs, byte sizes, LFS SHA-256s, and GitHub release digests via small Python one-liners rather than pasting raw API JSON into agent context.
6. **Clean merge cadence:** Rebase/fast-forward or squash-merge each reviewed slice into `release/3.2` immediately so worktrees stay tiny and `app.js` merge conflicts never accumulate.

### T3 Code Workspace Setup & UI Verification Strategy

- **Providers:** Configure both **Codex** (`codex` CLI → `Sol`) and **Google Antigravity** (`antigravity-acp` → `Neon`, `Argon`, `Terra`) against the local `meeting-transcriber` repository in T3 Code (`pingdotgg/t3code`).
- **Worktree dependency reuse (avoid repeated `npm ci` / `.venv` rebuilds):** Fresh Git worktrees do not copy gitignored `node_modules/` or `.venv/`. For code slices **A1–C2**, set `MAIN_CHECKOUT` to the absolute path of the main checkout, then symlink its dependencies from inside the worktree:
  ```bash
  ln -s "$MAIN_CHECKOUT/node_modules" node_modules
  ln -s "$MAIN_CHECKOUT/.venv" .venv
  ```
  Do **not** symlink `node_modules` or `.venv` for **Slice C3** (dependency upgrades) — use an isolated install or the main checkout so lockfile/wheel changes do not mutate other worktrees.

On Windows/macOS for final Checkpoint 3 packaged qualification, run interactive Computer Use directly in the native Codex or Antigravity desktop app rather than through T3 Code ACP.

## Phase 1: Device Compatibility Assessment, VRAM Calibration & Unload-Before-Install UX

### Task 1.1: Fix Compatibility Assessment & Calibrate Model Memory Guidance

**Files:**
- `src/ai-addon/summary-device-fit.js` — distinct fit statuses, nominal-GPU-tier tolerance, hardened `parseNvidiaMemory`
- `src/ai-addon-state.js` — recalibrated `memoryGuidance` across catalog models
- `src/main.js` — hardened Linux `nvidia-smi` resolution (`PATH` + standard locations, 10 s timeout, no 30 s negative cache on transient failure)
- `src/main/ai-addon-ipc.js` — resident-model context in live device checks; cold Linux `cudaStatus` handling
- `src/renderer/app.js` & `src/renderer/styles.css` — distinct badge mapping (`fits` / `likely_fits` / `tight` / `needs_more_memory` / `unknown`) and clear device-check copy
- `tests/js/summary-device-fit.test.js`, `tests/js/ai-addon-setup.test.js`

**Implementation:**
1. **Separate compatibility states in `getSummaryModelFit()` (`src/ai-addon/summary-device-fit.js`):**
   - Keep `status: 'unknown'` strictly for when `total == null` (hardware memory genuinely unreadable) — the **only** status that maps to `"Couldn’t check memory"` in the renderer.
   - Add `status: 'likely_fits'` (`blocked: false`, UI badge `"Compatible"` / `"Estimated fit"`, neutral/positive tone) when `total` meets `workingMemoryBytes` (within nominal tier tolerance) and `minimumRuntimeBytes`, even when `memoryGuidance.qualified !== true`. Reserve `status: 'fits'` (`"Verified fit"`) for host-qualified tiers.
   - Add `status: 'tight'` (`blocked: false`, amber warning badge `"Tight fit"`, NOT red `is-error`) when `total >= minimumRuntimeBytes` (and `available` is sufficient) but `total < nominalWorkingMemoryBytes`. Reserve `status: 'needs_more_memory'` (`blocked: true`, red `is-error`) for genuine hardware/VRAM insufficiency (`total < minimumRuntimeBytes` or `available < minimumRuntimeBytes` after accounting for unloaded state).
   - **Nominal VRAM rounding tolerance:** Real 12 GB NVIDIA GPUs (e.g., RTX 4070) report `12,282 MiB` (`11.994 GiB`), `6 MiB` below exact `12 * 1024^3`.
