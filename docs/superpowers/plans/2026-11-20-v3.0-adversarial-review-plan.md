## 1. Objectives & Review Rubric

Every chunk is audited **adversarially** against:
1. **Plan & Goal Fidelity**
   - `docs/superpowers/plans/2026-11-20-v3.0-release-plan.md` (Phases 1, 2, 4)
   - `docs/superpowers/plans/2026-11-20-v3.0-chat-design.md` (supersedes Task 4.3 UI layout)
   - Applicable canonical contracts in `docs/development/contracts/` (`recording.md`, `meeting-persistence.md`, `local-ai.md`, `packaging.md`, `ipc.md`)
2. **Security** — injection (command/shell, SQL/FTS5, XSS/HTML/Markdown, prompt injection), path traversal / symlink / tar-slip, auth/token/secret leakage (`LLAMA_API_KEY`, HF tokens, signing creds), SSRF / loopback / proxy bypass, fail-closed signing & checksum verification.
3. **Privacy** — zero cloud calls/telemetry/hidden downloads, deleted-meeting non-leakage in FTS5 search & Q&A, `userData`-only persistence, no ambient proxy leakage, no PII/secrets in logs/argv/errors.
4. **Race Conditions & Concurrency** — file-lock TOCTOU (`meetings.json.lock` vs `scan_recovery.lock`), SQLite WAL concurrent sync/search/rebuild, resident `llama-server` start/unload/idle-timer/cancel/competing-GPU-queue races, zombie child processes on crash/force-quit, `chat-thread-store.js` concurrent writes, renderer stale-async (`seq`) races.
5. **Functionality & Edge Cases** — legacy v1/v2 meetings without `.captions.json`, Windows reserved filenames & path quirks, Linux opaque device IDs & CUDA fail-closed rules, CJK/RTL/emoji UTF-8 byte budgets, audio seek before metadata load, broken/corrupt JSON/SQLite recovery.
6. **Performance & Resource Hygiene** — lock hold times on slow disks, FTS5 sync/query latency on large histories, VRAM/RAM release on unload, event-listener / DOM / timer leaks.
7. **Cross-Platform Static Audit Mandate (macOS & Windows on CachyOS Host):**
   Because this review runs on CachyOS Linux before live Windows/macOS testing, **never skip, skim, or defer Windows or macOS code paths**. Every subagent must audit Windows (`win32 x64`) and macOS (`darwin arm64`) code paths with extra scrutiny:
   - **Windows-specific traps:** open file-handle `EPERM`/`EBUSY` on `os.replace()` / `fs.rename()` / SQLite WAL rebuild or unlink; reserved basenames (`CON`, `NUL`, `COM1`, trailing dots/spaces); backslash vs forward-slash path confinement; Astral CPython `Lib/` + `DLLs/` + `python311._pth` + `_ctypes.pyd` + `nvidia_dll_loader.py` + Parakeet private launcher; `llama-server.exe` binary discovery and process-tree termination; Authenticode signing vs Speakrs CLI integrity hash; PowerShell quoting/exit-code handling in `verify-windows-installer.ps1`.
   - **macOS-specific traps:** Astral CPython `darwin-arm64` layout; `mlx_whisper_transcriber.py` caption cue extraction; Developer ID signing & notarization (`build/mac-sign.js`, `scripts/check-mac-signing-identity.js`, `scripts/notarize-macos-dmg.sh`, `scripts/verify-macos-*.sh`); nested binary signing order (`audiocapture-helper`, `speakrs-cli`, `ffmpeg`, Python dylibs) & Hardened Runtime entitlements; `notarytool` credential handling; `llama-server` unified-memory unload; `Cmd+Shift+3`/`4` shortcuts; `.github/workflows/build-release.yml` Windows & macOS jobs.
   - Tag platform-specific findings with `[Linux]`, `[Windows]`, `[macOS]`, or `[All]`, and note whether verification is covered by cross-platform unit tests on Linux or also requires Phase 5 host verification.

### Severity Scale
- **P0 (Blocker):** Security/privacy violation, data loss/corruption, deadlock/zombie leak, or broken contract invariant. **Must fix.**
- **P1 (High):** Real functional bug, race condition under plausible load, plan/goal gap, or brittle fail-open path. **Must fix.**
- **P2 (Medium):** Edge-case defect, performance bottleneck, missing negative test, or contract/doc drift. **Fix unless high churn for low gain.**
- **P3 (Low/Nit):** Style or minor cleanup. **Log only; do not dispatch Codex.**

## 2. Subagent Review Execution Model (8 Chunks, 93 / 93 Files)

To keep the main coordinator's context window clean:
- **Coordinator delegates all 8 review chunks to read-only Opus 5.5 subagents** (`invoke_subagent` with `TypeName: "research"`, `Model: "inherit"`).
- Launch subagents in **2 waves of 4** (Wave 1: Chunks 1–4; Wave 2: Chunks 5–8) so reviews run in parallel without flooding tool output.
- Each subagent:
  1. Reads only its chunk's canonical contract(s), relevant plan sections, and `git diff master...HEAD -- <chunk files>` (plus surrounding file context where needed).
  2. Performs full static adversarial review across Linux, **Windows**, and **macOS** code paths.
  3. Returns a **concise, structured report** (no raw diff dumps) containing:
     - Confirmed findings only (`ID`, `Severity`, `Platform`, `Category`, `File:Line`, `Concrete Bug/Exploit/Race`, `Required Fix`, `Testability on Linux vs Host`).
     - Cross-chunk boundary risks (e.g., an IPC or lock assumption that another chunk must verify).
     - Explicit confirmation of which files and macOS/Windows paths were inspected.
- The coordinator merges all 8 subagent reports into `<ArtifactDir>/scratch/review-ledger.md`, deduplicates/cross-checks boundary findings, and moves to Section 3 (Codex CLI remediation).

## 3. Remediation Workflow via Separate Codex CLI (`gpt-6.1-terra`) Sessions

After completing all 8 review chunks (or after every 2–4 chunks if the ledger grows large, though completing all 8 first avoids cross-chunk rework):

### Step A — Triage & Partition Findings into Fix Packets
Group all **P0**, **P1**, and worthwhile **P2** findings into **self-contained Fix Packets** (`FP-01`, `FP-02`, ...), where each packet:
- Owns a **strict, minimal list of target files** (no overlapping files across packets if any run in parallel; **default: run packets sequentially in the repo root** so diffs stay clean and verifiable one by one).
- Includes exact finding IDs, file paths + line numbers, reproduction/exploit scenario, required invariant/contract reference, and the exact focused test command Codex must run before finishing.

### Step B — Invoke Separate Codex CLI Sessions
Run each Fix Packet in its own fresh `codex exec` session pinned to `gpt-6.1-terra` (verified installed: `codex-cli 0.170.0`):

```bash
codex exec \
  -m gpt-6.1-terra \
  -c model_reasoning_effort="high" \
  -s workspace-write \
  --approve-for-me \
  -C /home/shareh/Projects/meeting-transcriber \
  -o "<ArtifactDir>/scratch/codex-FP-01.md" \
  - <<'EOF'
You are fixing specific adversarial code-review findings in /home/shareh/Projects/meeting-transcriber on branch release/3.0.

RULES:
- Read AGENTS.md and the listed contract(s) before editing.
- ONLY modify files relevant to the findings below (plus their matching tests). Do NOT refactor unrelated code. Do NOT run git commit/push/reset.
- Add or update regression tests proving each finding is fixed.
- Run the listed verification commands and report exact pass/fail results.

CONTRACTS TO READ:
- <contract paths>

FINDINGS TO FIX:
1. [ID] <Severity> <Title>
   - File(s): <path:line>
   - Issue: <exact bug / race / exploit / plan gap>
   - Required fix: <clear behavioral requirement>

VERIFICATION COMMANDS:
- <focused node --test / pytest commands>
EOF
```

> **Note on `--worktree`:** Only use `--worktree` if you intentionally run two completely disjoint packets in parallel; otherwise sequential `-C /home/shareh/Projects/meeting-transcriber` is faster, simpler, and avoids merge overhead.

### Step C — Opus Verification Gate (Per Packet)
Never trust a Codex worker's self-report blindly. After each `codex exec` exits:
1. Inspect `git diff` on the touched files line by line.
2. Verify the fix actually closes the root cause without breaking contracts, facade exports, or introducing new races/regressions.
3. Run the packet's focused tests yourself if needed (or confirm clean execution).
4. If inadequate, spawn a follow-up `codex exec` session (or `codex exec resume`) with the exact rejection reason.
5. Update `<ArtifactDir>/scratch/review-ledger.md` with status (`FIXED`, `VERIFIED`, `DEFERRED`, `WONTFIX`).

### Step D — Final Integrated Gate
Once all Fix Packets are verified:
1. Run `npm run test:all` and confirm exit `0`.
2. Inspect `git status` and full `git diff --stat` (ensure no stray scratch files were written inside the repo).
3. **Do NOT stage, commit, or push** (per `AGENTS.md` — leave git commit/push for explicit user authorization).
4. Deliver a concise executive summary artifact + response listing every finding by severity, what Codex fixed, what was verified, and any residual risks / manual hardware checks needed in Phase 5.
