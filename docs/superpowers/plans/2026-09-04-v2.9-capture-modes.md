# v2.9 Capture Modes Implementation Plan

> **For agentic workers:** Execute inline by default. Use a subagent only when the user requests it or the task crosses high-risk platform/process boundaries.

**Goal:** Add explicit mic-only and desktop-only recording options without changing existing mic-plus-desktop recording behavior.

**Architecture:** A closed capture-mode contract (`mic-and-desktop`, `mic-only`, `desktop-only`) crosses renderer, preload, main-process preflight/start handlers, and recorder command lines. Each recorder derives requested tracks from that contract before probing devices, creating capture spools, or starting capture threads; finalization keeps using the existing one- or two-track spool pipeline.

**Tech Stack:** Electron 44, plain HTML/CSS/JavaScript, Node IPC, Python 3.11 audio recorders, durable capture manifests and track spools.

## Architecture Change Record — 2026-09-04

**Why the plan expanded:** During desktop-only implementation, inspection established that `streaming_post_processor.finalize_capture()` rejects every capture manifest without a `mic` track and uses the microphone timeline as its output-duration authority. Recorder-only mode guards would therefore create a desktop-only spool that cannot be finalized or recovered.

**Approved change:** Generalize the bounded finalization and recovery contract to support one required primary track: `mic` for `mic-and-desktop` and `mic-only`; `desktop` for `desktop-only`. Preserve current mic-timeline geometry whenever microphone is present. A desktop-only manifest must never fabricate a mic track, mix unrequested audio, or change existing two-track output.

**Code-review focus:** Verify that primary-track selection is persisted in the manifest, validated before recovery/finalization, used consistently for duration/alignment/normalization, and covered by default-path regression tests. Verify desktop-only does not accidentally take mic enhancement or a mic-only fallback path.

## Global Constraints

- The primary Start Recording action remains `mic-and-desktop` and sends that value explicitly.
- Never infer capture mode from empty, sentinel, numeric, or opaque device IDs; Linux Pulse IDs remain opaque strings.
- An unrequested source must not be device-validated, permission-probed, opened, threaded, spooled, included in a manifest, or mixed into output.
- Preserve structured stdout, Stop/Discard first-command-wins behavior, recovery, duration accounting, transcription enqueueing, and existing macOS/Linux late-desktop policies when desktop is requested.
- Keep `src/main.js` composition-only. IPC payload changes update recorder service, preload, renderer call sites, and contract tests together.
- Automated tests establish behavior; Windows 10/11, macOS 14+ arm64, and Omarchy hardware evidence remains required before accepting the lane.

**Files:**

- Test: existing device/preflight tests that characterize `evaluateSelectedDevices`

**Implementation:** Define one closed, main-process-owned mode normalizer. `undefined` is normalized only at the API boundary to `mic-and-desktop` for compatibility with existing trusted callers; unknown values are rejected with a stable invalid-mode response. Every new renderer request supplies the explicit value.

Pass `captureMode` through `run-recording-preflight` and `start-recording`. Device validation receives source requirements derived from the mode and validates only requested IDs. macOS microphone permission status is queried only if the mode requests microphone capture; desktop-only must not invoke that probe. Preserve disk and desktop-output diagnostics where source-independent, but do not make a single-source recording fail because its unrequested source is absent.

Build argv with `--capture-mode <mode>` for every platform, retaining opaque `pulse-source:` / `pulse-monitor:` values verbatim. Add contract tests covering explicit default, both single-source modes, omitted legacy mode, invalid mode, device validation isolation, permission isolation, and unchanged default argv behavior.

**Validation:** `node --test tests/js/recorder-service.deps.test.js tests/js/recorder-event-contract.test.js tests/js/ipc-contract-snapshot.test.js`

### Task 2: Make every recorder create and capture only requested tracks

**Files:**
- Modify: `backend/audio/windows_recorder.py`

**Implementation:** Add the same closed `capture_mode` constructor/CLI contract to each recorder, with CLI default `mic-and-desktop` for direct-invocation compatibility. Reject invalid values before opening audio APIs. Derive `include_mic` and `include_desktop` once and use them to gate device checks, desktop helper/loopback initialization, spool creation, startup readiness waits, capture thread creation, levels, manifests, and finalization inputs.

Mic-only never initializes/probes desktop capture. Desktop-only never queries/opens microphone or starts its thread; success and output duration derive from desktop timeline. The default stays two-track and preserves platform-specific degradation policy. A requested desktop failure in desktop-only is terminal rather than silently saving microphone audio; requested mic failure remains terminal. Keep cancel/recovery valid for either one-track manifest.

Add test-first characterization for every platform: each mode opens only its source, starts expected threads/spools, produces matching manifest/finalization tracks, and rejects invalid modes. Preserve existing two-track tests as default-regression tests, including Linux opaque source handling and macOS late-desktop behavior.

**Validation:** `.venv/bin/python -m pytest tests/python/test_windows_recorder.py tests/python/test_macos_recorder.py tests/python/test_linux_recorder.py -q` and `npm run test:python-syntax`
