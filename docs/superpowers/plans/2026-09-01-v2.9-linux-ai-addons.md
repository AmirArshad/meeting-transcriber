# v2.9 Linux AI Add-ons Implementation Plan

> **For agentic workers:** Execute inline by default. Use a subagent only when the user requests it or the task crosses high-risk platform/process boundaries.

**Goal:** Add CUDA Whisper, CUDA-only Speakrs diarization, and CUDA-only local summaries to v2.9.0 for the supported CachyOS x86_64 + NVIDIA RTX 4070 profile.

**Architecture:** Extend the existing catalog, GPU-runtime service, shared GPU-resource queue, add-on setup, and packaged-resource workflows; do not create Linux-specific queues or recorder paths. Each runtime/engine becomes available only after its own pinned-artifact, integrity, packaged, and RTX 4070 hardware gates pass; otherwise it stays unavailable without a CPU or cloud fallback.

**Tech Stack:** Electron 44.1.0, Node CommonJS, Python 3.11, faster-whisper/CTranslate2, CUDA 12-compatible NVIDIA runtime, Rust Speakrs CLI/ONNX Runtime, llama.cpp, CachyOS x86_64/Hyprland/PipeWire.

## Global Constraints

- The only supported Linux AI profile is CachyOS x86_64, Hyprland/Wayland + PipeWire, NVIDIA RTX 4070. Other Linux distributions, desktop environments, GPUs, and driver stacks remain experimental and must not acquire a support claim from this work.
- No cloud transcription, summaries, telemetry, or background uploads. Summary generation remains an explicit user action.
- Linux AI is CUDA-only. Missing/incompatible CUDA, validation failure, or unsupported hardware must leave the affected action unavailable; do not retry it on CPU.
- Use `aiComputeActionQueue` for transcription, diarization, and generation; use `gpuResourceActionQueue` for CUDA install/repair/uninstall, model preload, and compute admission. Do not introduce a second queue or an idle-wait fail-fast path.
- All artifacts must be catalog-pinned, HTTPS allowlisted, full-SHA-256 verified, size recorded, and extracted through existing traversal guards. A user-writable manifest never authorizes a binary, model pack, or runtime.
- Linux is Speakrs-only. Speakrs never reads or accepts a Hugging Face token; Linux Pyannote requests remain rejected in the main process. Windows/macOS retain their existing exclusive Speakrs/Pyannote selector and token protections.
- Packaged Linux Python stays isolated through `buildPythonEnv()` and must not inherit ambient `PYTHONPATH`, `PYTHONHOME`, or user-site packages. Linux child-library paths must point only to managed runtime directories.
- Preserve existing Windows/macOS behavior and tests. Non-GPU CI is test coverage only; no CI result may be presented as Linux GPU acceptance.
- Version/release metadata changes only on `release/v2.9.0` after all accepted feature lanes are independently green.

Linux uninstall must be lifecycle-safe: while holding `gpuResourceActionQueue`, atomically rename/tombstone the active runtime, invalidate the CUDA cache, then delete only the tombstone. No deletion or timed-out install may continue against the active path after timeout/quit releases the resource slot.

Keep Windows/macOS behavior, queues, cancellation, timeouts, quit behavior, IPC contracts, and facade export shapes. Linux Core Beta remains CPU when the profile is not enabled.
