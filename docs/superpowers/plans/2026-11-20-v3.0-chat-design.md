## 1. Visual & Interaction Design (`Chat` Rail Module)

### Subject, Audience & Signature
AvaNevis is a calm, local-first meeting recorder and transcriber for users who want searchable, verifiable recall across private recordings without cloud dependencies. The `Chat` view acts as a quiet **evidence ledger and conversation studio**: every factual answer is visibly anchored back to exact local meeting timestamps via interactive citation pills (`[Meeting Title · MM:SS]`), and local model memory remains explicitly inspectable and controllable via a live memory-lifecycle pill in the header.

### Design Token Alignment (Existing AvaNevis Dark System)
Reuse AvaNevis's existing CSS design tokens verbatim in `src/renderer/styles.css`:
- **Surfaces:** `--surface-0` (`#101214`), `--surface-1` (`#171a1d`), `--surface-2` (`#202428`), `--surface-3` (`#252a2e`), `--surface-4` (`#2b3136`), `--surface-glass` (`rgba(23, 26, 29, 0.94)`).
- **Hairlines:** `--hairline` (`#343a40`), `--hairline-strong` (`#434a50`), `--hairline-soft` (`#292e32`).

1. **Collapsible Thread Sidebar (`.chat-sidebar`):**
   - Header with sidebar toggle button (and responsive drawer overlay below `900px`) + `+ New chat` primary action.
   - Instant thread title filter input.
   - Chronological recency buckets (`Today`, `Yesterday`, `Previous 7 Days`, `Older`).
   - Thread item displays title, subtle scope badge (`All History` or scoped meeting pill), inline rename (`Enter` commits, `Escape` cancels), and delete with confirmation.
2. **Chat Header & Model Memory Status Pill (`.chat-header`):**
   - Active thread title + scope summary badge.
   - Live **Local Model Memory Pill** reflecting `history-qa-model-state`:
     - `unloaded` → neutral slate indicator: `Not loaded`
     - `loading` → animated pulse indicator: `Loading…`
     - `loaded` → emerald indicator: `Loaded in memory · <Model>` + explicit one-click **`Unload`** button
     - `unloading` → muted amber indicator: `Unloading…`
3. **Conversation Canvas (`.chat-stream` inside `max-width: 760px` centered column):**
   - **Calm Empty State:** Introduces grounded local Q&A with clickable starter prompts tailored to existing meetings/scope.
   - **Turns:** Right-aligned elevated user message cards; airy editorial assistant prose rendered offline via bundled `marked` (`18.2.1`) + strict `DOMPurify` (`3.4.18`) allowlist (headings `h1`–`h4`, GFM tables, lists, blockquotes, fenced code blocks with one-click **Copy** button; zero raw HTML links/scripts/images/event handlers).
   - **Inline Citation Pills & Sources Drawer:** Only verified `evidenceId` markers (`[E1]`..`[En]`) returned by `citation_verifier.py` render as interactive `<button class="chat-citation-pill">` chips displaying `[Meeting Title · MM:SS]` (styled consistently with History timestamp badges), paired with an expandable `<details>` **"Sources (N)"** drawer listing speaker, date, timestamp, and verbatim excerpt.
   - **Live Progress & Queue Banner:** Inline status line showing retrieval, queue wait (`"Queued behind active transcription…"`), model loading, or local generation, with cancellation support.
   - **Insufficient Evidence Callout:** Calm amber-bordered notice explaining no matching passages or verified citations supported an answer (no fabricated claims).
   - **Honest Add-on Onboarding State:** History full-text search (Task 4.1) is always active without any AI add-on. Opening `Chat` when the local Qwen / `llama.cpp` summary add-on is not installed (or unsupported on the machine) shows an honest onboarding card explaining local Q&A uses the local Summary AI add-on with a one-click jump to **Settings → AI Add-ons** (never auto-downloading).
4. **Floating Bottom Composer Dock (`.chat-composer-dock`):**
   - Auto-growing multiline `<textarea>` (`Enter` sends, `Shift+Enter` inserts newline, respects IME `isComposing`).
   - Scope selector pill & popover: `All History`, `Selected meetings…` (multi-select checklist of meetings), and optional `From` / `To` date filters.
   - Context-aware **Send** / **Stop** action button.
5. **Cross-Module Deep-Links:**
   - **Citation Click (`Chat` → `History`):** Validates the cited meeting still exists (graceful non-blocking toast if deleted); activates `History`, selects the meeting, ensures the `Transcript` detail tab is active, scrolls to and highlights the closest timestamped transcript segment (`.is-citation-highlight`, respecting `prefers-reduced-motion`), and seeks `<audio id="audio-player">` + custom scrubber to `startSec`.
   - **History → Chat Hand-off:** Add an **`Ask in Chat`** button (`#ask-meeting-in-chat-btn`) inside History's `.meeting-detail-actions` that switches to `Chat` and creates/reuses a thread scoped to that meeting.
   - **History Sidebar Full-Text Search (Task 4.1):** `#meeting-search` queries the local SQLite FTS5 index, displays matched snippet highlights (`<mark>` via `textContent`) and clickable `[MM:SS]` jump chips on meeting items using the same `openMeetingAtTimestamp()` deep-link path.

## 2. Lazy Model Load & Manual / Automatic Unload Lifecycle

### Memory & Latency Strategy
- **Zero-VRAM idle default:** Never start `llama-server` on app launch or when switching to the `Chat` tab.
- **Zero-hit preflight gate:** Every `ask-history` invocation first syncs the SQLite FTS5 index and runs `backend/history_qa/retrieval.py` *before* acquiring `aiComputeActionQueue` or loading the model. If `evidence` is empty, return `insufficient_evidence` immediately with `modelLoaded: false`.
- **Warm resident `llama-server` with `llama-cli` fallback:**
  - Across all 3 pinned runtimes (`win32-x64` b9173, `darwin-arm64` b9173, `linux-x64` ai-dock v0.3.0), `llama-server` (`.exe` on Windows) lives beside `llama-cli` inside `runtimeDir/extract`. (Verified on CachyOS Linux: `cuda-12.8/llama-server`, 14,592 bytes, SHA-256 `e24d8686017f6dc7be39c7563a24cf9383e54aca6627af53a3898f1e4b736d19`, sharing already-pinned `libllama-server-impl.so`).
  - Keep existing `SUMMARY_RUNTIME_ARTIFACTS` `executableName` (`llama-cli`) and `requiredFiles` backward compatible for existing installed summaries; verify `llama-server[.exe]` strictly as a regular, non-symlink sibling inside the verified `executableDir` inside `runtimeDir/extract` (and on Linux verify its SHA-256 and byte size). If absent, transparently run single-turn `llama-cli`.
- **Strict Loopback & Auth Security:**
  - Allocate an ephemeral TCP port bound strictly to `127.0.0.1` (never `0.0.0.0`).
  - Generate a fresh per-launch 256-bit secret (`crypto.randomBytes(32).toString('hex')`). Pass it exclusively via `LLAMA_API_KEY` env var to `llama-server` and via stdin JSON to `qa_runner.py` (never CLI argv, logs, crash messages, or renderer).
  - Launch `llama-server` with `--host 127.0.0.1 --port <port> --model <gguf> --ctx-size 32768 --n-gpu-layers -1 --parallel 1 --no-webui --reasoning off`.
  - Poll `http://127.0.0.1:<port>/health` with `Authorization: Bearer <token>` (cancelling cleanly if aborted).
  - `qa_runner.py` verifies `serverUrl` has `scheme == 'http'` and `hostname == '127.0.0.1'`, uses `urllib.request.build_opener(urllib.request.ProxyHandler({}))` (bypassing ambient proxy env vars), and never exposes the token in stdout/stderr.
- **Manual Unload (`unload-history-qa-model`):**
  - Cancels any in-flight `ask-history` generation if active, transitions state `unloading`, terminates `llama-server` via `terminateProcessBestEffort` and awaits process exit so GPU VRAM / unified memory is genuinely released, clears bearer token and idle timer, and emits `history-qa-model-state` `{ status: 'unloaded' }`.
- **Automatic Safety Unloads (All 4 Hard Requirements):**
  1. **Competing GPU/Compute Admission:** Unload resident `llama-server` before any transcription, diarization, guided transcription, summary generation, Whisper preload, or CUDA runtime action runs on `aiComputeActionQueue` / `gpuResourceActionQueue`.
  2. **Idle Auto-Unload:** 10-minute inactivity timer (`.unref()`'d) resets on each completed query and unloads `llama-server` when idle.
  3. **Add-on Mutation Gate:** Unload before Summary add-on setup, validation, repair, or removal.
  4. **Quit Lifecycle:** `drainAiWorkBeforeQuit()` aborts active Q&A and awaits `llama-server` shutdown; `onForceQuit` invokes a synchronous process-tree kill backstop.

## 3. Data Persistence Schemas (`userData` Only)

### Search Index Cache (`userData/search/history-index.sqlite`)
- Disposable derived SQLite FTS5 cache (`journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`).
- Tables: `index_meta`, `indexed_meetings`, `passages` (`kind IN ('title', 'transcript', 'summary')`), `passages_fts` (`unicode61 remove_diacritics 2`).
- Rebuilt atomically from `meetings.json` + `.md` + `{stem}.captions.json` + summary sidecars on schema mismatch or `sqlite3.DatabaseError`. Hard-deletes removed meetings on every sync so deleted recordings never leak into search or Q&A.

### Chat Thread Store (`userData/chat/threads.json`)
- Managed exclusively by main-process `src/main/chat-thread-store.js` with serialized writes (same-dir temp file + `fsync` + `rename` and corrupt backup `threads.corrupt.<timestamp>.json`).
- Schema v1:
  ```json
  {
    "schemaVersion": 1,
    "threads": [
      {
        "id": "thread_<uuid>",
        "title": "Q4 launch timeline",
        "createdAt": "2026-11-20T12:00:00.000Z",
        "updatedAt": "2026-11-20T12:05:00.000Z",
        "scope": {
          "type": "all | selected_meetings",
          "meetingIds": [],
          "dateFrom": null,
          "dateTo": null
        },
        "messages": [
          {
            "id": "msg_<uuid>",
            "role": "user | assistant",
            "content": "...",
            "createdAt": "...",
            "status": "answered | insufficient_evidence | error",
            "citations": [
              {
                "evidenceId": "E1",
                "meetingId": "meeting_20261115_100000",
                "meetingTitle": "Q4 Planning",
                "meetingDate": "2026-11-15T10:00:00",
                "startSec": 862,
                "endSec": 884,
                "speaker": "Speaker 1",
                "excerpt": "...",

            ],

  }
  ```
- Deleting a meeting from History leaves historical chat messages intact, while citation pills gracefully show a non-destructive toast (*"This meeting is no longer in History."*) when clicked and follow-up turns retrieve only against live History.
