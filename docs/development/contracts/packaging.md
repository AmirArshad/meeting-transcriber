# Packaging contract

Keep `prepare-resources`, download manifest pins/tests, `package.json` extra resources, and runtime path resolution aligned. Prepared resource manifests must invalidate stale resources. Speakrs CLI and validation fixture are bundled and integrity-checked fail-closed; hash raw bytes, not decoded executable text. Speakrs models are explicit setup-time downloads.

Packaged Python must set `AVANEVIS_PACKAGED=1`, ignore ambient Python paths, set `PYTHONNOUSERSITE=1` and `PYTHONDONTWRITEBYTECODE=1`, while allowing managed add-on paths ahead of bundled backend. Linux tray uses PNG assets and skips Tray construction without an SNI watcher. macOS ad-hoc signing, helper staging/signing, and updater filename coupling remain verified release gates.

### Platform traps

- **Windows save dialogs:** file basenames are sanitized against `WINDOWS_RESERVED_FILE_BASENAME` by `buildSafeSaveDialogDefaultPath` (`src/main/file-export-ipc.js`). A meeting titled `CON`, `PRN`, `AUX`, `NUL`, `COM1`… is unwritable on Windows even with an extension. Do not bypass that helper when adding an export path.
- **macOS tray icon:** call `setTemplateImage(false)` **before** `setImage` for the saturated recording-status icon. Template images get auto-tinted monochrome, which silently destroys the red REC indicator.
- **Windows capture cleanup:** see **Python backend** below — the lock must be released before `rmtree`.

### Build packaging

Keep aligned when bundled runtime locations or prepared-resource inputs change: `build/prepare-resources.js`, `build/download-manifest.js` (pinned URLs + checksums, with `tests/js/build-download-manifest.test.js`), `package.json` `extraResources`, and path resolution in `src/main.js`. Generated `build/resources/resource-manifest.json` must keep invalidating stale prepared resources. `prepare-resources.js` builds and stages `Resources/bin/speakrs-cli[.exe]` plus the validation fixture WAV; fail the build if that binary is missing. Build the 0.7 product CLI with the locked native CUDA or CoreML features and Rust 1.89.0. The CPU smoke tool has its own Cargo manifest and stays in CI and local qualification. The v2.11 app Info.plist and bundled Rust CLI target macOS 15.0, an approved exception to the prior baseline. Keep the Swift audio helper deployment target and capture compatibility checks independent.

Windows packaged Python uses unified Astral standalone `3.11.18+` (`Lib/`, `DLLs/`, explicitly authored isolated `python311._pth` containing `../backend`, `./Lib/site-packages`, `./Lib`, `./DLLs`, `.`, and `import site`); dev relies on `PYTHONPATH` set in `src/main.js`. Packaged macOS/Linux python-build-standalone **does** honor `PYTHONPATH`.

Parakeet's private Windows interpreter disables `import site` (`-S -P`) and must retain
both the packaged Python root and its `DLLs` directory as standard-library / extension
import roots when `DLLs/_ctypes.pyd` (or root `_ctypes.pyd`) is present. Exclude stdlib
`Lib/site-packages`, `Lib/test`, `Lib/tkinter`, `Lib/idlelib`, and `Lib/ensurepip` from
the Windows runtime root and keep the explicitly authored `python311._pth` isolation intact.

**Packaged-only path hardening.** Packaged apps set `process.env.AVANEVIS_PACKAGED=1` at main-process startup (so worker threads inherit it) and inject it via `buildPythonEnv()` for every Python child. Packaged `buildPythonEnv()` must not inherit ambient `PYTHONPATH`, `PYTHONHOME`, or `PYTHONUSERBASE`, must set `PYTHONNOUSERSITE=1`, and must force `PYTHONDONTWRITEBYTECODE=1` so normal recorder/transcriber/add-on subprocesses cannot mutate the signed app bundle with `__pycache__`. Caller-supplied `PYTHONPATH` extras (managed add-on site-packages) may still prepend the bundled backend path. When set, `backend/audio/swift_audio_capture.py` must **not** call `shutil.which("audiocapture-helper")` — only the bundled `Resources/bin/audiocapture-helper` or explicit dev build paths are valid. Summary tar extraction (`resolvePreferredTarExecutable`) likewise prefers absolute system tar over PATH. Dev/`npm start` leaves the var unset so PATH lookup still works.

**Release asset naming & differential metadata.** `src/updater.js` and `src/main/updater-service.js` identify installers by the `AvaNevis-Setup-${version}.${ext}` filename pattern (`package.json` `build.artifactName`). `package.json` configures `build.publish` (`github` `AmirArshad/meeting-transcriber`) and macOS `dmg` + `zip` (`arm64`) targets alongside Windows NSIS (`differentialPackage: true`) and Linux `AppImage`/`pacman`/`deb`. User-facing package and tray metadata (`package.json` `description`, `linux.synopsis`, `linux.desktop.entry.Comment`, `mac.extendInfo.CFBundleDisplayName`, `nsis.shortcutName`, and the idle tray tooltip) uses **Audio Recorder & Transcriber** positioning, while `productName` (`AvaNevis`), `appId` (`com.avanevis.app`), `build.artifactName`, and `build.publish` remain unchanged. Tagged releases in `.github/workflows/build-release.yml` publish the five primary installers plus `AvaNevis-Setup-${version}.zip`, `latest.yml`, `latest-mac.yml`, `latest-linux.yml`, and `*.blockmap` so both `electron-updater` v3+ clients and legacy v2.x clients resolve releases cleanly. Change artifact naming in `package.json` or `.github/workflows/build-release.yml` and you must update `src/updater.js` and `src/main/updater-service.js` too.

**Tray assets.** `resolveTrayImageFileName` (`src/main/recording-presence-service.js`) owns the per-platform tray image. Linux must use PNGs (`iconTrayLinux.png`, `iconTrayLinuxRecording.png`) — `nativeImage.createFromPath` cannot decode `.ico` outside Windows and returns an **empty** image, while `new Tray(emptyImage)` still succeeds on Linux, so the failure mode is a registered-but-invisible SNI item rather than an exception. Linux `createTray()` also probes `org.kde.StatusNotifierWatcher` via `busctl --user status` before constructing a Tray: Electron 44 `new Tray()` does **not** throw when no SNI host is running, and a successful constructor would make close **hide** with no visible icon. Missing watcher skips tray creation so idle/recording close **minimizes**. Any new tray image must also be added to `package.json` `extraResources`. Regeneration commands are in `docs/development/MACOS_ICONS.md`.

**macOS & Windows signing and notarization.** `package.json` keeps `build.mac.identity: "-"` and `build.mac.notarize: false` so certificate-less PR/local builds cleanly ad-hoc sign via Gate B ([issue #76](https://github.com/AmirArshad/meeting-transcriber/issues/76)). `npm run build:mac` runs `scripts/check-mac-signing-identity.js` (`--preflight` / `--run`), which injects Developer ID / `notarytool` flags dynamically when signing credentials are present and fails closed on partial creds or ad-hoc fallback when `AVANEVIS_REQUIRE_SIGNED_RELEASE=1`. `npm run build` / `build:dir` runs `scripts/check-win-signing-config.js` to configure Windows Authenticode signing (Azure Trusted Signing or `WIN_CSC_LINK`/cert-store) and likewise enforces `AVANEVIS_REQUIRE_SIGNED_RELEASE=1`. In `.github/workflows/build-release.yml`, tagged releases automatically sign, notarize, and verify signatures whenever signing secrets are configured, allow unsigned Windows / ad-hoc macOS releases when no signing secrets are set, and enforce fail-closed signing (`AVANEVIS_REQUIRE_SIGNED_RELEASE=1`) when `vars.REQUIRE_SIGNED_RELEASE=true` (or `workflow_dispatch` `require_signed_release=true`). On macOS, `src/main/updater-service.js` inspects the packaged `.app` signature (`isMacAppDeveloperIdSigned`) and selects `manual-package` (`.dmg`) on ad-hoc builds while automatically enabling Squirrel.Mac `in-app` updates on Developer ID builds. To preserve raw-byte Speakrs integrity verification (`scripts/verify-speakrs-packaging.js --packaged`) across Authenticode / Mach-O code signing, `build/after-pack.js` (`win32`) refreshes `resources/bin/speakrs-integrity.json` after `WinPackager` signs `extraResources`, and `build/mac-sign.js` (`darwin`) runs `@electron/osx-sign`, refreshes `Contents/Resources/bin/speakrs-integrity.json`, and re-seals only the outer `.app` without `--deep` before notarization. `scripts/notarize-macos-dmg.sh`, `scripts/verify-macos-packaged-app.sh`, `scripts/verify-macos-installer.sh`, and `scripts/verify-windows-installer.ps1` verify signatures, timestamps, and notarization tickets.
